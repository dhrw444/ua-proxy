# ua-proxy 管理面板 · 部署与使用

一个 Worker 干四件事：**代理**、**内嵌管理面板**、**配置存 D1**、**聚合上游密钥**。

---

## 一、它解决什么

| 原来 | 现在 |
|---|---|
| 提示词是代码常量，改一个字要重新部署 | 面板上改，保存即生效 |
| 22 个反引号把模板字符串干断 | 存 D1，不经 JS 字符串，不用转义 |
| 域名一泄露谁都能白嫖额度 | `ACCESS_KEY` 鉴权 + 可改的访问前缀 |
| 只有一个星驰 key，打满就停 | 密钥池，出错自动切换 |

---

## 二、部署（五步）

### 1. 建 D1 库

```bash
wrangler d1 create ua-proxy
```

把返回的 `database_id` 填进 `wrangler/wrangler-5-panel.toml`。

### 2. 建表（手动跑一次）

```bash
wrangler d1 execute ua-proxy --remote --file=./schema.sql
```

**只跑一次，一辈子。** 表建好之后代码就假定它存在。

> `--remote` 是打在 Cloudflare 上的真库。不加就是本地测试库。
> 没有 `wrangler` 就在后台面板的 D1 → Console 里把 `schema.sql` 的内容粘进去执行，效果一样。

### 3. 设密码

```bash
wrangler secret put ADMIN_PASSWORD    # 面板登录密码，必填
wrangler secret put ACCESS_KEY        # 客户端调代理用的 key，必填
wrangler secret put SESSION_SECRET    # 可选，会话签名用
```

`SESSION_SECRET` 设了之后，改 `ADMIN_PASSWORD` 不会把已登录的会话踢掉。不设就用密码当签名密钥——那样一改密码所有设备都要重登。

### 4. 部署

```bash
wrangler deploy
```

### 5. 进面板

打开 `https://你的域名/`，输密码。

## 三、面板能改什么

### 注入模式

| 模式 | 位置 | 取舍 |
|---|---|---|
| `append` | system 末尾 | 稳。但落在缓存断点后，每轮全额计费 |
| `prepend` | system 最前 | **进缓存前缀，省钱**。权重略低 |
| `replace` | 删掉客户端 system | 最强势，工具调用容易坏 |
| `last-user` | 塞进末条 user 消息 | **遵从度最高**，不省缓存 |

15KB 提示词约 4200 token。`append` 每轮全额付，`prepend` 命中缓存后只要 10%。**差 10 倍，每轮都在付。**

### 提示词

大文本框，直接粘贴。实时显示字符数。存 D1，反引号和 `${` 都不用转义。

### 访问前缀

```
点「随机生成」→ 得到 8 位小写字母数字
点「保存前缀」→ 立刻生效
```

开启后：

```
https://你的域名/a7f3k2m9/v1/messages   ← 能用
https://你的域名/v1/messages             ← 404
https://你的域名/wrong999/v1/messages    ← 404
```

**面板本身的路径不受影响**，`/` 和 `/api/*` 照常。

### 密钥池

往里填星驰的 key，客户端就不用再自带 key 了：

```
客户端 ──ACCESS_KEY──▶ Worker ──池里选一个──▶ 星驰
```

星驰真 key 永远不出 Worker。

## 四、密钥池怎么工作

### 粘性（默认）

每个客户端**钉住一个 key**，只有该切的时候才换。

```
首次见到  → 按 clientId 哈希定位到一个 key，钉住
请求成功  → 什么都不做
该切了    → 游标 +1，此后一直用新的
```

**为什么不是轮询**：星驰的 prompt cache 按 key 算。每轮换 key 等于永久放弃缓存，15KB 提示词每轮全额计费。粘性既保缓存又保稳定。

### 什么时候会切

| 上游返回 | 切？ | 原因 |
|---|---|---|
| **429** | **切** | 额度打满 / 限速 |
| **401 / 402 / 403** | **切** | key 失效、欠费、被封 |
| **500 / 502 / 503 / 529** | 不切 | 上游整体挂了，换 key 没用 |
| **400 / 422** | 不切 | 请求本身有问题，不是 key 的锅 |

最后一行是重点。**收到 400 就换 key，等于把健康 key 一个个打进冷宫。**

### 不换回来

切走之后**不会**因为「冷却到期」自动换回原 key。只前进，环形走一圈。

每天 UTC 0 点重置游标——这样被换下去但额度已恢复的 key 能重新分到活。

### 全挂了

N 个 key 全部失败 → 返回最后一个上游响应（不包装，错误原样透传）。
异常情况 → 503 `所在上游密钥均不可用`。

## 五、客户端怎么接

```
Base URL   https://你的域名/<前缀>
key        ACCESS_KEY
```

三种带 key 的方式都认：

```
x-api-key: <ACCESS_KEY>              ← Anthropic 系客户端天然带这个
Authorization: Bearer <ACCESS_KEY>   ← OpenAI 系客户端天然带这个
?key=<ACCESS_KEY>                    ← 都不支持的走这个
```

**不用改客户端协议，它原本带哪个就填哪个。**

`?key=` 会在转发前从 URL 剥掉，不会进上游日志。

## 六、安全设计

| 做了什么 | 为什么 |
|---|---|
| 会话 = `过期时间.HMAC(密码指纹+过期时间)` | 无状态。**改密码 → 指纹变 → 所有旧 Cookie 立即失效** |
| `timingSafeEq` 常数时间比较 | 挡按时序猜密码 |
| Cookie `HttpOnly; SameSite=Lax`，HTTPS 加 `Secure` | 防 JS 读、防跨站携带 |
| 非 GET 校验 `Origin` 同源 | 挡 CSRF |
| 同 IP 失败 8 次锁 10 分钟 | 挡爆破 |
| 未登录时 HTML 里不渲染任何配置 | 密码都没进，别想看到提示词 |
| 前缀错误返回 **404** 而不是 401 | 401 等于告诉扫描器「这里有个受保护的服务」 |
| 面板列密钥时打码 | 只显示前 4 位和末 4 位 |

**`ACCESS_KEY` 不设 = 代理完全公开。** 面板上会显示黄色警告。别留着。

## 七、D1 用量

设计目标是免费额度永远用不完。

| 操作 | 频次 | 行数 |
|---|---|---|
| 读配置 | 每 30 秒最多一次（isolate 内存缓存兜住） | 2 行读 |
| 面板保存 | 你点一次 | 1 行写 |
| 加/删密钥 | 你点一次 | 1 行写 |
| 代理请求 | **0** | **0** |

一天 2000 个请求、改 5 次配置：

```
读 ≈ 几百行 / 500 万行免费额度 = 0.01%
写 = 5 行 / 10 万行免费额度
```

**关键：密钥游标和失败计数只存内存，不进 D1。** 否则每请求一次写，10 万行/天几天就烧光。

## 八、自检

```bash
curl https://你的域名/health
```

```json
{"ok":true,"mode":"prepend","upstream":"https://api.xingchiapi.com",
 "promptLength":15039,"suffixOn":true,"keyCount":2,
 "db":true,"accessKeySet":true}
```

- `keyCount: 0` → 密钥池空，客户端得自带 key
- `accessKeySet: false` → 没设 ACCESS_KEY，谁都能用
- `db: false` → D1 没绑，面板保存会失败

## 九、边界

- **面板是单页、无客户端路由。** 故意如此——Worker 的静态资源 fallback 会把 `/v1/messages` 吃掉。
- **前缀不是加密。** URL 会进浏览器历史和 CDN 日志。它挡的是「不知道地址的人」，真正挡人的是 `ACCESS_KEY`。
- **密钥游标是内存状态。** isolate 重启就回落到哈希初值，代价是最多白试一次坏 key。
- **配置缓存 30 秒。** 改完立刻生效的只有当前 isolate，其他最长 30 秒。
- **提示词注入只影响请求体**，改不了模型权重。这是能做的全部。

## 十、和前面四版的关系

| 文件 | 提示词在哪 | 面板 | 代理鉴权 | 密钥池 |
|---|---|---|---|---|
| 1-ua-only | 无 | 无 | 无 | 无 |
| 2-full | 代码常量 | 无 | 无 | 无 |
| 3-env | `env.PROMPT` | 无 | 无 | 无 |
| 4-blank | 留空自填 | 无 | 无 | 无 |
| **5-panel** | **D1，面板改** | **有** | **有** | **有** |

5 号是唯一不用重新部署就能改配置的，也是唯一能挡白嫖、能多 key 分摊的。

# 测试

四个脚本，都**不需要网络**——D1 和上游都是本地 mock。

```bash
node tests/audit.mjs    # 功能审计   115 项
node tests/t5d1.mjs     # 单元       68 项
node tests/e2e5d1.mjs   # 真实 TCP   36 项
node tests/tools.mjs    # 生成器     12 项
```

在仓库根目录或 `tests/` 里跑都行，路径按脚本位置推导。

## 各测什么

### `audit.mjs` — 功能审计

把每个声称的功能单独立项，逐条验，输出一张分组表：

```
■ 面板        16 项   登录页/主面板/提示词框/四模式/前缀框/密钥框/保存/退出
■ 鉴权        10 项   401/伪造 cookie/改密码失效/无密码/限速 429
■ CSRF         3 项   跨站 403、同源通过、无 Origin 放行
■ 配置        14 项   六个字段读写、四种 mode、非法值拒绝、无 D1 报错
■ 前缀        16 项   带/不带/错前缀、非法值、换前缀旧地址失效
■ 代理鉴权     7 项   三种带 key 方式、?key= 剥离、未设时放行
■ 注入        12 项   四模式位置、三协议、UA 改写、空提示词、幂等
■ 密钥池      11 项   增删改查、掩码、短密钥、停用
■ 选 key       9 项   粘性、分散、429 切/400 不切、first 策略
■ 响应         5 项   剥 content-encoding/length、透传、OPTIONS
■ 路径         1 项   前缀剥离后路径和 query 都干净
■ health       5 项   匿名只回 ok、登录给细节、不吐提示词
■ 长文本       3 项   20039 字符往返一致、完整注入
```

失败会带实测值，比如 `← got 503`。

### `t5d1.mjs` — 单元

不经过 HTTP，直接调 `worker.fetch(Request, env)`。测逻辑分支：会话签名、CSRF 判定、D1 读写、密钥选择、注入位置。

还有一条专门的：**15039 字符提示词经 D1 往返后逐字节一致**。

### `e2e5d1.mjs` — 真实 TCP

起真的 `http.Server` 当上游和代理，走真 socket。抓的是只有真实网络栈才暴露的问题：

- `transfer-encoding` 被原样转发 → upstream 拒收
- gzip 响应体的 `content-encoding` 没剥 → 客户端解压崩溃
- 40KB 大 body 触发 chunked
- SSE 流式透传

这三个曾经都是真 bug。

### `tools.mjs` — 生成器

`tools/set-prompt.mjs` 把提示词写进 TOML 的 `'''` 字面量。TOML 会吃掉开头换行、保留结尾换行——**曾在闭合前多一个换行，把 15039 字符写成 15040**。

这个脚本验：字节数、字符数、sha256、反引号数量、`tomllib` 标准解析。

## 双向验证

写完测试不代表测试有效。要证明它抓得住 bug，得把修复逐个回退，看测试会不会红。

`docs/` 里记录了 7 个关键修复的双向验证结果，全部命中：

| 回退什么 | 测试反应 |
|---|---|
| `shouldRotate` 恒返回 false | 2 项失败 |
| body 读两次（无法重放） | 6 项失败 |
| 前缀门禁失效 | 3 项失败 |
| `maskSecret` 直接返回原文 | 2 项失败 |
| 跨站检查失效 | 1 项失败 |
| 粘性改成永远第一个 | 2 项失败 |
| 404 改成 401 | 2 项失败 |

## mock 的边界

`tests/d1mock.mjs` 是个模式匹配的假 D1，只实现 worker 用到的那几条 SQL。它**不验证 SQL 语法**——真 SQL 写错只有部署后才能发现。

所以部署后建议先跑一遍：

```bash
curl https://你的域名/health
```

`{"ok":true}` 说明路由通，登录后拿到完整 JSON 说明 D1 也通。

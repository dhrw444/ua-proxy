# 安全设计

## 威胁模型

这个 Worker 只有一个管理员（你）。攻击面是**公网可访问的 URL**。

要防的是三件事：

1. 别人用你的上游额度（花钱）
2. 别人改你的提示词（改 AI 行为）
3. 别人读你的配置（知道你在干什么）

不防的是：能读你 Cloudflare 账号的人。那种权限已经能改 Worker 代码了，加密挡不住。

---

## 三道门

### 第一道：访问前缀（隐蔽）

```
/abc12345/v1/messages   ← 能用
/v1/messages            ← 404
```

**返 404 不返 401。** 401 等于告诉扫描器「这里有个受保护的服务，来试吧」。404 让它以为什么都没有——连页面里都不出现 "ua-proxy" 字样。

前缀错了也是 404，不给「前缀存在但不对」这个信息。

**但前缀不是加密。** URL 会进：

- 浏览器历史
- CDN / 代理日志
- `Referer` 头
- 你自己的截图

所以它是**隐蔽层**，不是**认证层**。

### 第二道：ACCESS_KEY（认证）

```
x-api-key: <ACCESS_KEY>
Authorization: Bearer <ACCESS_KEY>
?key=<ACCESS_KEY>
```

三种都认，因为不同客户端带 header 的习惯不同——不用改客户端的协议。

**常数时间比较**（`timingSafeEq`），长度也走同一循环，不按长度提前返回。

`?key=` 会在转发前从 URL 剥掉，不进上游日志。

**不设 ACCESS_KEY = 完全公开。** 面板会亮黄色警告。

### 第三道：面板密码（管理）

`ADMIN_PASSWORD` 存 secret，不落盘。

## 会话机制

Cookie 里存的不是密码，是这个：

```
<过期时间戳>.<HMAC-SHA256(密码指纹 | 过期时间戳)>
```

四个后果：

1. **服务端不存 session**，不查库，纯验签
2. **改密码 → 指纹变 → 所有设备立刻掉线**
3. **7 天过期**，`Max-Age` 和签名里的时间戳双重校验
4. **`SESSION_SECRET` 解耦**：设了之后改密码不会踢会话

Cookie 属性：

```
HttpOnly           JS 读不到（XSS 偷不走）
SameSite=Lax       跨站 POST 不带
Secure             HTTPS 下才发
```

`HttpOnly` 是真生效的——我实测过用 `document.cookie = 'ua_session=; Max-Age=0'` 清不掉，只能走 `/logout` 让服务端下发。

## CSRF

所有非 GET 的 `/api/*` 都校验 `Origin`：

```
Origin 存在且 host 不等于本站  → 403
Origin 不存在（curl、脚本）    → 放行
Origin 等于本站                → 放行
```

**为什么放行无 Origin 的请求**：`curl`、服务端脚本、Postman 都不带 Origin。拦了它们没意义——它们本来就不受浏览器同源策略约束，也不是 CSRF 的攻击载体。

---

## 爆破防护

同一 IP 失败 8 次 → 锁 10 分钟（内存计数，各 isolate 独立）。

**已知局限**：Cloudflare 会起多个 isolate，每个各算各的。挡得住单点爆破，挡不住分布式慢速试探。

**这种情况换强密码更快。** 12 位以上随机密码，试到宇宙热寂也试不出来。

## 信息泄露清单

| 端点 | 匿名能看到 |
|---|---|
| `GET /` | 登录页（无任何配置） |
| `GET /health` | `{"ok":true}` 一个字段 |
| `GET /api/*` | `{"error":"未登录"}` |
| 前缀错误的代理路径 | 404 页（无任何标识） |

**曾经 `GET /health` 匿名就吐 `upstream`、`promptLength`、`keyCount`** —— 开了前缀也白开，扫一下 `/health` 就把上游地址和家底全看走了。已修。

登录后才给完整信息（但这些也不含密钥和提示词正文）。

## 密钥存储

上游密钥**明文存 D1**。

理由：能读到这个库的人，已经能改你的 Worker 代码了。加密挡不住他，只会让你自己多记一个密码。加密在这里是**表演**，不是安全。

面板显示时打码：长于 8 位的显示 `前4位…后4位`，短的直接 `****`。

**曾经有个 `tail` 字段返回 `secret.slice(-4)`** —— 密钥短于 4 位时返回全文。已删。

---

## 上游密钥不下发

```
客户端 ──ACCESS_KEY──▶ Worker ──真 key──▶ 上游
```

客户端永远看不到上游真 key。密钥池有内容时，客户端带来的 key 会被替换掉，不会出现在上游请求头里。

---

## 这份设计的边界

**挡不住的**：

- 能读你 Cloudflare 账号的人（能改代码）
- 拿到 `ACCESS_KEY` 的人（他就是你）
- Cloudflare 内部（它本来就是你的代理）

**挡得住的**：

- 扫端口找代理的机器人
- 拿到域名但没拿到 key 的人
- 拿旧 Cookie 复用（改密码即失效）
- CSRF（跨站伪造的 POST）
- 暴力破解（8 次锁 10 分钟 + 强密码）

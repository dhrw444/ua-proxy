# <span style="color:#8957e5;">一、怎么改</span>

## <span style="color:#8957e5;">方式 1：环境变量（推荐）</span>

<span style="color:#4a4a4a;">不用动代码，改配置就行。</span>

**<span style="color:#24292f;">wrangler 部署</span>** — 改 toml 的 `[vars]`：

```toml
[vars]
MODE = "last-user"
```

然后重新部署：

```bash
npx wrangler deploy -c wrangler/wrangler-3-env.toml
```

**<span style="color:#24292f;">Dashboard 部署</span>** — 依次点：

<span style="color:#57606a;">`Settings` → `Variables and Secrets` → 加 `MODE` → 填值 → `Deploy`</span>

<div style="border-left:4px solid #cf222e; padding:10px 14px; background:#fff5f5;">

<span style="color:#cf222e;">**必须点 Deploy。** 不点不生效，这是最常见的「改了没反应」原因。</span>

</div>

---

## <span style="color:#8957e5;">方式 2：改代码常量</span>

<span style="color:#4a4a4a;">打开 js 文件，找到第 361 行左右：</span>

```js
const MODE = "append";
```

<span style="color:#4a4a4a;">改成你要的值，重新部署。</span>

---

## <span style="color:#8957e5;">优先级</span>

```js
const rawMode = String(env.MODE || MODE).toLowerCase().trim();
```

<span style="color:#8957e5;">**环境变量 > 代码常量。**</span>

| 情况 | 实际生效 |
|---|---|
| 只设了环境变量 | <span style="color:#2ea043;">环境变量</span> |
| 只改了代码常量 | <span style="color:#2ea043;">代码常量</span> |
| 两个都设了 | <span style="color:#d29922;">**环境变量**</span>（常量改动被忽略） |
| 填了非法值 | <span style="color:#2ea043;">自动回退 `append`</span>，不会崩 |

<div style="border-left:4px solid #d29922; padding:10px 14px; background:#fffbeb;">

<span style="color:#9a6700;">**第三条最容易踩**：你在代码里改了，但 Dashboard 里早就有一个 `MODE` 变量，结果一直是老值。</span>

</div>

# <span style="color:#1f6feb;">二、四种模式实测</span>

<span style="color:#57606a;">客户端原本的 system 假设有两块：`客户端A`、`客户端B`，其中 B 带缓存断点。`⛁` = `cache_control` 缓存断点。</span>

## <span style="color:#2ea043;">append（默认）</span>

```
system: [0]客户端A  [1]客户端B⛁  [2]你的规则
末条:   user:问题
```

## <span style="color:#1f6feb;">prepend</span>

```
system: [0]你的规则  [1]客户端A  [2]客户端B⛁
末条:   user:问题
```

## <span style="color:#d29922;">replace</span>

```
system: 字符串:你的规则
末条:   user:问题
```

## <span style="color:#cf222e;">last-user</span>

```
system: [0]客户端A  [1]客户端B⛁
末条:   user:问题⏎你的规则
```

---

# <span style="color:#2ea043;">三、逐个说明</span>

## <span style="color:#2ea043;">append — 默认值</span>

| 项 | 内容 |
|---|---|
| 位置 | 追加到 system 数组末尾 |
| 优点 | 客户端规则完整保留，工具调用不会坏 |
| 缺点 | <span style="color:#9a6700;">落在缓存断点之后，每轮按未缓存计费</span> |
| 用在哪 | <span style="color:#2ea043;">默认就用这个，最稳妥</span> |

---

## <span style="color:#1f6feb;">prepend</span>

| 项 | 内容 |
|---|---|
| 位置 | 插到 system 数组最前 |
| 优点 | <span style="color:#2ea043;">进缓存前缀，第一轮付一次，之后免费</span> |
| 缺点 | <span style="color:#9a6700;">你的规则排在客户端前面，权重更低，容易被压住</span> |
| 用在哪 | 只想要省钱，且效果已经够用 |

---

## <span style="color:#d29922;">replace</span>

| 项 | 内容 |
|---|---|
| 位置 | 删掉客户端全部 system，只留你的 |
| 优点 | <span style="color:#2ea043;">最强势，客户端规则彻底消失</span> |
| 缺点 | <span style="color:#cf222e;">**会坏工具**，见下方警告</span> |
| 用在哪 | 客户端规则明显在跟你作对，且你不需要它的工具 |

<div style="border-left:4px solid #cf222e; padding:12px 16px; background:#fff5f5;">

<span style="color:#cf222e;">**会坏工具。**</span> <span style="color:#4a4a4a;">如果客户端靠 system 里的工具定义工作（文件读写、代码执行），删掉后模型可能不按格式调用工具，功能直接废掉。</span>

<span style="color:#57606a;">实测：`replace` 会把 `system` 从数组换成字符串。Anthropic 两种类型都接受，所以不会报错，但客户端的工具规范也一起没了。</span>

</div>

---

## <span style="color:#cf222e;">last-user — 遵从度最高</span>

| 项 | 内容 |
|---|---|
| 位置 | 拼到最后一条 user 消息后面，system 一字不动 |
| 优点 | <span style="color:#2ea043;">**指令以「用户说的话」身份出现，绕开 system 层面的规则竞争**</span> |
| 缺点 | <span style="color:#9a6700;">会进对话历史，多轮之后可能被后续消息冲淡</span> |
| 用在哪 | <span style="color:#cf222e;">前面几种都压不住时用这个</span> |

---

# <span style="color:#d29922;">四、该用哪个</span>

## <span style="color:#d29922;">决策顺序</span>

<span style="color:#2ea043;">**append**</span> → <span style="color:#cf222e;">**last-user**</span> → <span style="color:#d29922;">**replace**</span>

## <span style="color:#d29922;">按场景选</span>

| 场景 | 用哪个 | 理由 |
|---|---|---|
| <span style="color:#2ea043;">加点自己的风格，不冲突</span> | `append` | 默认，什么都不用改 |
| <span style="color:#9a6700;">客户端塞了一堆规则限制你</span> | <span style="color:#cf222e;">**`last-user`**</span> | 降维成用户输入，绕开 system 竞争 |
| <span style="color:#cf222e;">last-user 也不管用</span> | `replace` | 但接受工具功能可能坏 |
| <span style="color:#1f6feb;">效果够用，想省钱</span> | `prepend` | 进缓存前缀 |

<div style="border-left:4px solid #cf222e; padding:12px 16px; background:#fff5f5;">

<span style="color:#cf222e;">**三种都不行怎么办？**</span>

<span style="color:#4a4a4a;">说明拦截发生在模型权重层面或上游服务端，这个 Worker 改不了。换上游或换客户端，别再折腾 MODE。</span>

</div>

---

# <span style="color:#0d9488;">五、怎么验证</span>

## <span style="color:#0d9488;">第一步：看清客户端发了什么</span>

<span style="color:#4a4a4a;">把客户端的 Base URL 临时改成：</span>

```
https://<你的域>/__inspect
```

<span style="color:#4a4a4a;">发一条消息，返回该软件实际发出的完整请求体。</span>

关键字段：

| 字段 | 含义 |
|---|---|
| <span style="color:#0d9488;">`systemPromptLength`</span> | 客户端塞了多少字的规则 |
| <span style="color:#0d9488;">`systemPromptPreview`</span> | 规则前 500 字 |
| <span style="color:#0d9488;">`messageCount`</span> | 对话轮数 |
| <span style="color:#0d9488;">`bodyBytes`</span> | 请求体总大小 |

<div style="border-left:4px solid #d29922; padding:10px 14px; background:#fffbeb;">

<span style="color:#9a6700;">**这一步很重要。** 不看清对手是什么，换模式都是瞎试。</span>

</div>

---

## <span style="color:#0d9488;">第二步：用能一眼看出的提示词测试</span>

<span style="color:#4a4a4a;">把 `PROMPT` 临时改成：</span>

```
你的每条回复必须以 [INJ] 开头，然后正常回答。
```

<span style="color:#4a4a4a;">部署，随便问一句。</span>

| 结果 | 含义 |
|---|---|
| <span style="color:#2ea043;">回复开头有 `[INJ]`</span> | <span style="color:#2ea043;">注入成功，提示词进了模型上下文</span> |
| <span style="color:#cf222e;">回复开头没 `[INJ]`</span> | <span style="color:#cf222e;">上游剥离或重写了 system，这个上游不支持注入</span> |

---

## <span style="color:#0d9488;">第三步：对比不同 MODE</span>

<span style="color:#4a4a4a;">同一个提示词，分别试 `append` / `last-user` / `replace`，看哪个能压住客户端规则。</span>

<span style="color:#4a4a4a;">每次改完**记得重新部署**。</span>

---

# <span style="color:#cf222e;">六、几个坑</span>

## <span style="color:#cf222e;">坑 1：改了 MODE 但没生效</span>

<span style="color:#4a4a4a;">两个原因：</span>

1. <span style="color:#cf222e;">环境变量改了没点 **Deploy**</span>
2. <span style="color:#cf222e;">代码常量和环境变量都设了，**环境变量赢了**，但你以为改的是常量</span>

---

## <span style="color:#cf222e;">坑 2：提示词里的反引号导致语法错</span>

<span style="color:#4a4a4a;">模板字符串里：</span>

| 字符 | 要写成 |
|---|---|
| <span style="color:#cf222e;">`` ` ``</span> | <span style="color:#2ea043;">`` \` ``</span> |
| <span style="color:#cf222e;">`${`</span> | <span style="color:#2ea043;">`\${`</span> |

<span style="color:#4a4a4a;">不想手工转义就用 `src/agentrouter-3-env.js`，提示词放 `prompt.txt`：</span>

```bash
node tools/set-prompt.mjs prompt.txt
```

---

## <span style="color:#d29922;">坑 3：append 每轮都在计费</span>

<span style="color:#4a4a4a;">因为落在 `cache_control` 断点之后，每轮都按未缓存算。</span>

<span style="color:#2ea043;">换 `prepend` 就进缓存了</span><span style="color:#4a4a4a;"> —— 代价是权重变低。</span>

---

## <span style="color:#d29922;">坑 4：replace 之后工具不能用了</span>

<span style="color:#4a4a4a;">正常。客户端靠 system 里的工具定义工作，删了就没了。</span>

<span style="color:#2ea043;">换回 `append` 或 `last-user`。</span>

---

## <span style="color:#d29922;">坑 5：last-user 多轮之后效果变弱</span>

<span style="color:#4a4a4a;">正常。你的规则在第一轮就进了历史，后面聊得越多，它在上下文里的占比越低。</span>

<span style="color:#4a4a4a;">长对话里如果发现又开始听平台的，开新会话。</span>

---

# <span style="color:#57606a;">七、多轮会不会累积</span>

<span style="color:#2ea043;">**不会。**</span> <span style="color:#4a4a4a;">注入内容带 `[ua-proxy]` 标记，检测到已存在就跳过。</span>

<span style="color:#4a4a4a;">实测六轮：</span>

| 轮次 | messages 数 | 标记数 | body 体积 |
|---|---|---|---|
| 1 | 1 | <span style="color:#2ea043;">1</span> | 15796 B |
| 2 | 3 | <span style="color:#2ea043;">1</span> | 15885 B |
| 3 | 5 | <span style="color:#2ea043;">1</span> | 15974 B |
| 4 | 7 | <span style="color:#2ea043;">1</span> | 16063 B |
| 5 | 9 | <span style="color:#2ea043;">1</span> | 16152 B |
| 6 | 11 | <span style="color:#2ea043;">1</span> | 16241 B |

<span style="color:#4a4a4a;">标记数恒为 1，体积增长只来自对话本身。</span>

<div style="border-left:4px solid #2ea043; padding:10px 14px; background:#f0fff4;">

<span style="color:#1a7f37;">**为什么不能整包 `JSON.stringify` 查重**：Claude Code 每轮把完整会话重发，几百 KB 每轮序列化一次不值。代码只检查会被写入的那个字段。</span>

</div>
